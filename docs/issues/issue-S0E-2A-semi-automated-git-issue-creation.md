## Context

- Formalize a v1 contract for semi-automated Git issue creation derived from structured logs.
- Fix a controlled title keyword vocabulary so issue naming stops drifting across parent and child issues.
- Fix a labels taxonomy and automation-level matrix, including which labels must remain manual.
- Add issue-aware frontmatter fields to parent and phase log templates so future issue scaffolds can be generated from stable inputs.

## Definition of Done (DoD)

- A controlled `fixed-keyword` vocabulary is fixed and its usage boundaries are documented.
- The labels taxonomy clearly separates `full-automation`, `semi-automation`, `three-quarter automation`, and `zero-automation` cases.
- The contract explicitly states that GitHub labels must be pre-created rather than generated ad hoc.
- The issue body scaffold and milestone fallback rules are defined.
- The `log frontmatter -> issue fields` mapping is defined and reflected in the parent and phase templates.
- This issue draft can be used as the first `log -> issue scaffold` sample for validation.
